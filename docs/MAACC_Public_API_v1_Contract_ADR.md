# MAACC Public API v1 Contract ADR

**Decision:** ADR-P2-001

**Status:** Approved implementation baseline

**API contract:** 1.0.0

**Schema dialect:** `https://maacc.dev/schema/compact/1.0`

**Approved by:** Aminu Hussain, Change Owner
**Effective:** 18 July 2026

This ADR freezes the enterprise-remediation implementation contract. It does not replace the multi-role organizational approval still required by gate G0, and it does not authorize real sensitive data while readiness containment remains active.

## Decision

The `/api/v1` route family remains the stable URI major. Every response declares semantic contract version `1.0.0` through `X-Maacc-Api-Version`; `GET /api/v1/sdk` and the manifest publish the same version. PHP and TypeScript SDK `1.0.0` are the supported clients. Pre-v1 SDKs are reported as `upgrade_required`.

All JSON request bodies must be valid UTF-8 JSON with no duplicate object keys, including keys that are equivalent after escape decoding. Duplicate or malformed JSON returns `invalid_json` before framework decoding. Objects are closed unless the schema explicitly sets `additionalProperties: true`.

### Compact schema 1.0

MAACC formally versions its compact schema rather than claiming JSON Schema 2020-12 compliance. A field definition is either a legacy scalar string such as `string`, `integer?`, or `string·date`, or a rich definition with:

- `type`: `string`, `number`, `integer`, `boolean`, `object`, or `array`;
- `required`, `format`, `enum`, `minimum`, `maximum`, `minLength`, `maxLength`, `minItems`, and `maxItems`;
- nested object `properties` and explicit `additionalProperties`;
- array `items`.

Arguments are decoded, validated, projected to declared fields, and size-checked before persistence or execution in every tool mode. Results are bounded before parsing and are validated, projected, and size-checked before persistence or model use. The server, both SDK validators, shared fixtures, generated stubs, and manifest all declare the same dialect.

### Run lifecycle

`requires_tool` is the transient model decision that a tool must run. It is not a durable API pause. A client-side request is first materialized as a tool call, then the durable run status becomes `waiting_for_client`. SDK consumers must branch on `waiting_for_client`; the `requires_tool` compatibility token remains recognized through the 1.x window and is scheduled for removal in 2.0.0, no earlier than 18 January 2027.

Durable statuses are `queued`, `running`, `waiting_for_client`, `requires_approval`, `completed`, `failed`, `expired`, and `cancelled`. Terminal statuses are `completed`, `failed`, `expired`, and `cancelled`.

### Caller context

Applications obtain a short-lived HMAC-signed envelope from `POST /api/v1/caller-contexts`. Claims include version, application/environment audience, opaque subject, optional approved department/roles, issue/expiry time, correlation ID, and optional nonce. MAACC verifies audience, environment, signature, lifetime, and vocabulary, stores only minimized claims, includes them in run responses, and supplies them to PHP and TypeScript tool contexts. The legacy free-form `caller` field is informational and never grants access.

### Manifest and execution provenance

The manifest is application, environment, tenant, and scope aware. It includes applicable global client tools. Implementation state is derived as `required`, `not_required`, or `disabled` before normal compatibility states.

Publication and every run persist a secret-free snapshot containing prompt, model identity and eligibility evidence, tool versions/schemas/configuration, sensitivity, approvals, routing, application/project environment, governance timestamp, schema version, and runtime policy version. Public runs bind the immutable published agent version. Authorized console draft tests are marked `is_test`, record their initiating user, retain a run snapshot, and never publish the agent or expose a public invocation bypass.

## Compatibility and change control

- Additive optional fields and new error codes may ship in API 1.x with synchronized fixtures and SDK support.
- Removing or changing a field, status meaning, schema rule, or signature input requires API and SDK 2.0.0.
- A deprecation must declare `deprecated_in`, `removed_in`, and a migration guide. The minimum window is 180 days for supported enterprise clients unless a security issue requires faster removal and an approved exception is recorded.
- Contract changes are one release unit: server, shared fixtures, PHP SDK, TypeScript SDK, generated artifacts, reference consumers, examples, BRS reconciliation, architecture reconciliation, and migration guidance.

## Verification

The shared fixture suite is generated by `php artisan maacc:sdk-fixtures` and consumed by both SDKs. Server feature tests pin JSON duplicate handling, nested schema behavior, caller-context verification, status behavior, manifest scope/status derivation, governed draft testing, and execution snapshots.
